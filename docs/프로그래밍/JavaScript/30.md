## 키워드

- 메모리 관리
- 도달 가능성
- 루트
- mark-and-sweep

## 요약

- GC는 자바스크립트 엔진에서 자동으로 수행됩니다. (개발자가 임의로 실행하거나 막을 수 없습니다)
- 자바스크립트에서 도달 가능성을 기준으로 메모리를 관리합니다.
- 참조된다고 해서 도달 가능성이 있는 것은 아니다. 서로 연결된 객체들도 도달 불가능할 수 있습니다. (도달할 수 없는 섬)
- GC는 mark-and-sweep 알고리즘을 사용합니다.

## 가비지 컬렉터 (Garbage Collector)란?


가비지 컬렉터는 자바스크립트 엔진 내에서 자동으로 메모리 관리를 수행하고, 개발자가 임의로 실행하거나 막을 수 없습니다.


자바스크립트는 **도달 가능성**이라는 개념을 도입해서 이를 기준으로 객체의 삭제 여부를 결정합니다.


### 도달 가능성


자바스크립트는 도달 가능성(Reachability)라는 개념을 도입하여 메모리를 관리합니다.


도달 가능성이란 어떻게든 접근해서 사용할 수 있는 값을 의미하고, 도달 가능한 값은 메모리에서 삭제되지 않습니다.


아래의 값은 도달 가능한 값으로 명백한 이유 없이는 삭제 되지 않습니다.

- 현재 함수의 지역 변수와 매개변수
- 중첩 함수의 체인에 있는 함수에서 사용되는 변수와 매개변수 (클로저)
- 전역 변수

위의 값들을 **루트** 라고 부릅니다.


> 루트가 참조하는 값이나 스코프 체이닝으로 루트에서 참조할 수 있는 값은 모두 도달 가능한 값이 됩니다.


자바스크립트 엔진 내에서 GC가 동작하면서 모든 객체를 모니터링하고, 도달할 수 없는 객체를 삭제합니다.


### 간단한 예시


{% raw %}
```
javascript
let user = {
  name: "John"
};

```
{% endraw %}


위의 예제에서 전역 변수 `user`는 `{ name = ‘kane’ }` 객체를 참조합니다.

### 연결된 객체


객체가 서로 연결된 경우에 외부에서 들어오는 참조만 도달 가능한 상태에 영향을 줍니다. (루트에서 도달 가능한지가 중요)


{% raw %}
```
javascript
function marry(man, woman) {
  woman.husband = man;
  man.wife = woman;

  return {
    father: man,
    mother: woman
  }
}

let family = marry({
  name: "John"
}, {
  name: "Ann"
});

```
{% endraw %}

{% raw %}
```
javascript
delete family.father;
delete family.mother.husband;

```
{% endraw %}

### 도달할 수 없는 섬


객체들이 연결되어 하나의 섬 같은 구조를 만드는데, 이 섬에 도달(참조)할 수 없는 경우 섬 전체가 메모리에서 삭제됩니다.


위 family 예시에서 family 객체에 null을 덮어쓰면 아래와 같은 구조로 변경됩니다.


{% raw %}
```
javascript
family = null;

```
{% endraw %}

## 알고리즘


GC는 mark-and-sweep 알고리즘을 사용한다. 프로세스는 다음과 같습니다.

1. GC는 루트 정보를 수집하고 mark(기억)합니다.
2. 루트가 참조하고 있는 모든 객체를 방문하고 이것도 mark합니다.
3. mark된 모든 객체에 방문하고 그 객체들이 참조하는 객체도 mark합니다. (한번 방문한 객체는 mark하기 때문에 같은 객체를 다시 방문하지 않습니다)
4. 루트에서 도달 가능한 모든 객체를 방문할 때까지 반복합니다.
5. mark 되지 않은 모든 객체를 메모리에서 삭제합니다

## 최적화 기법


GC에서 가비지 컬렉션이 수행할 때 프로그램이 멈추게 되는데, 이를 stop-the-world라 합니다. 이 시간이 길어질수록 성능에 영향을 주게 되는데,


이를 해결하기 위해 V8 엔진에서는 Orinoco 프로젝트를 통해 성능 최적화 방법을 발전시켰습니다.


### Incremental


작업을 분할해서 메인 스레드의 지연 시간을 해결해서 실행 속도를 증가시키는 방식입니다.


{% include lazyload.html image_src="https://devshjeon-blog-images.s3.ap-northeast-2.amazonaws.com/_images/%ED%94%84%EB%A1%9C%EA%B7%B8%EB%9E%98%EB%B0%8D/JavaScript/%EA%B0%80%EB%B9%84%EC%A7%80%20%EC%BB%AC%EB%A0%89%ED%84%B0%20%28Garbage%20Collector%29/7.webp" %}


### Parallel


메인 스레드와 헬퍼 스레드가 거의 동일한 양의 작업을 동시에 수행하는 방식입니다.


이 방식은 여전히 stop-the-world가 발생할 수 있지만, 스레드 수로 나눈 시간만큼 stop-the-world 시간이 줄어듭니다.


{% include lazyload.html image_src="https://devshjeon-blog-images.s3.ap-northeast-2.amazonaws.com/_images/%ED%94%84%EB%A1%9C%EA%B7%B8%EB%9E%98%EB%B0%8D/JavaScript/%EA%B0%80%EB%B9%84%EC%A7%80%20%EC%BB%AC%EB%A0%89%ED%84%B0%20%28Garbage%20Collector%29/8.webp" %}


### Concurrent


메인 스레드가 자바스크립트를 지속적으로 실행하고 헬퍼 스레드는 GC 작업만 수행하는 방식입니다.


메인 스레드가 오직 자바스크립트만 실행하기 때문에 stop-the-world는 발생하지 않는 장점이 있지만, 동시에 동일한 객체를 메인 스레드와 헬퍼 스레드가 접근할 때 읽기/쓰기 경쟁 및 힙 영역이 지속적으로 변경되어 이전 작업이 무효화 될 수 있는 단점이 있어 가장 어려운 방식입니다.
